# 작업 전 보고서 검토

## 목표

Javis가 A01의 작업 전 보고서를 Gmail에서 읽고, 같은 보고서의 재발송은 한 작업으로 묶은 뒤 범위와 완료 기준을 검토한다. 이 기능은 기존 메일 답장 작업과 별도인 `/widget-work` 화면에서만 보인다.

## 처리 순서

1. 운영자가 `보고서 메일 가져오기`를 누른다.
2. 서버는 최근 7일 받은편지함에서 첨부가 있는 `검토 요청` 메일만 검색한다.
3. `JARVIS_WORK_REPORT_SENDERS`에 등록한 발신자만 받는다.
4. 작업 ID, 보고서 버전, 첨부 내용 다이제스트로 원본과 재발송을 같은 보고서에 연결한다.
5. 필수 계약 검사가 목표, 저장소·기준 버전, 허용·제외 범위, 완료 증거를 확인한다.
6. 계약이 맞으면 도구 없는 A01 모델 검토를 실행한다. 계약이 틀리면 모델을 호출하지 않고 A01 보완 필요 상태로 돌린다.
7. 통과 판정은 코드 수정·테스트·commit·push·PR 작성까지만 허용한다. main 병합과 운영 배포는 이 기능에 없다.

## 운영 설정

`runtime.env`에 쉼표로 구분한 허용 발신자를 설정한다. 실제 주소는 저장소에 커밋하지 않는다.

```text
JARVIS_WORK_REPORT_SENDERS=a01@example.com
```

설정이 없으면 수집 API는 `503`으로 중단한다. 발신자 주소, 첨부 HTML, 보고서 본문은 계정별 DB 행에 저장되고 웹 인증을 통과한 같은 계정에서만 조회할 수 있다. HTML은 화면 안에서 실행하지 않고 인증된 다운로드로만 제공한다.

## 상태

| 상태 | 뜻 | 다음 단계 |
|---|---|---|
| `collected` | 새 보고서를 저장함 | Javis 검토 |
| `needs_revision` | 계약 누락 또는 A01 검토 반려 | A01이 내용을 고치고 새 버전 전송 |
| `needs_user` | 사용자만 정할 수 있는 범위가 있음 | 사용자 질문 |
| `passed` | 구현·테스트·PR 단계로 진행 가능 | 별도 A01 전달 연결 |

`passed`는 실행 완료가 아니다. 현재 변경은 A01 작업 전달, A03 코드 실행, 이메일/Telegram 알림을 수행하지 않는다.

## 현재 MIMO v1.0.0 판정 예상

현재 보고서는 제외 범위에 `commit·push`를 넣었으므로 새 정책과 충돌한다. Javis는 다음 내용으로 `needs_revision`을 반환해야 한다.

- 코드 수정·테스트·commit·push·PR 작성은 허용 범위에 추가
- main 병합·운영 배포만 사용자 확인 전 금지
- 내용을 바꿨으므로 보고서 버전을 올려 재전송

## 검증

```text
cd server
uv run python -m unittest test_work_reports test_widget_planning -v

cd ..
npm run test:bridge
npm test -- --run
npm run build:live
```

단위 검사는 기존 보고서의 범위 충돌, 수정 보고서 통과, 원본·재발송 중복 제거, 계약 실패 시 모델 미호출, HTML 다운로드 보존을 확인한다.
