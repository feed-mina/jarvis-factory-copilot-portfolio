## 예상안

## Before: 정적 소스 설명 기반 모형

현재 MIMO 상품 목록의 정적 근거 기반 재구성

- Firebase 상품 객체의 title, price, content, imgUrl을 입력으로 사용한다.
- GET /itmes.json 결과의 객체 키를 id로 변환한 뒤 MainListItem을 반복 표시하는 구조로 보고되어 있다.
- 카드는 이미지, 제목, 가격 및 설명을 표시하며 기존 원천은 Firebase Realtime Database 상품 노드다.
- 로딩과 오류 분기는 보고되어 있으나 빈 목록의 명시적 화면 계약은 정리가 필요하다.
- MainListItem에서 사용하는 item.Url이 보고된 입력 매핑에 포함되지 않아 선택 이동의 근거가 불일치한다.
- 운영 앱 실행, 실제 Firebase 응답, 고객 화면 동등성 및 모바일 동작은 확인되지 않았다.
- 기존 링크 클릭으로 이동하는 동작이 있으나 item.Url의 생성·검증 방식은 정적 근거만으로 확정할 수 없다.
- 상품 조회 외 수정·주문·결제는 현재 파일럿 비교 대상에서 제외한다.
- 문제 발생 시 되돌릴 수 있도록 기존 MainList 경로를 유지한다는 계획이 필요하지만, 실제 전환 장치의 형태는 확인되지 않았다.

## After: 제안 모형

제안 모형: 읽기 전용 MIMO 상품 카드 목록

- 입력 계약은 items 배열과 status로 나눈다. 각 항목은 itemId, title, price, content, imgUrl을 가지며 itemId는 선택 이벤트에 필요한 필수 식별자다.
- title은 카드 제목, price는 상품 가격 표시값, content는 설명, imgUrl은 대표 이미지 주소다. 값의 실제 형식·통화 규칙은 호스트가 정규화하고 표시 부품은 가격 계산을 하지 않는다.
- 상태 계약은 loading, empty, error, ready로 제한한다. ready에서는 1개 또는 다수 카드를 표시하고, 빈 배열은 실패가 아니라 empty로 표시한다.
- 이미지 누락·로드 실패 시 상품명 기반 대체 문구와 고정 대체 영역을 표시한다. 허용되지 않은 외부 출처는 직접 불러오지 않고 동일한 대체 상태로 처리하는 정책을 제안한다.
- 연습 자료는 0개, 정상 1개, 정상 다수, 조회 실패를 기본 세트로 두고, 이미지 누락·긴 title·긴 content·매우 긴 가격 표시값을 추가 변형으로 둔다.
- Firebase 호스트 어댑터가 GET /itmes.json 조회, 오류 변환, 객체 키의 itemId 변환 및 원본 필드 정규화를 담당한다. 카드·목록 화면은 Firebase 주소나 응답 형식을 알지 못한다.
- 모바일에서는 단일 열 또는 가용 폭에 맞는 카드 배치를 사용하고 텍스트가 화면 밖으로 넘치지 않게 한다. 긴 문구는 줄바꿈 또는 시각적 생략을 적용하되 접근 가능한 이름이나 상세 표현에서 전체 의미를 보존한다.
- 유일한 상품 행동 계약은 select(itemId)다. 포인터 클릭과 키보드 Enter 또는 Space가 같은 itemId를 한 번 전달하며, 이벤트 자체는 저장·이동·주문을 실행하지 않는다.
- 기존 item.Url은 새 입력 계약에서 제외한다. 선택 후 이동이 필요하면 호스트가 itemId를 검증해 목적지를 결정하며, URL이 없거나 안전하지 않으면 이동하지 않는다.
- KMovement의 open(contentId)는 select(itemId)와 같은 선택 계열로 대응시키지만 toggleSave(contentId)는 대응시키지 않는다.
- 저장, 주문, 결제, 찜, 상품 수정, 분석 이벤트 및 외부 전송은 파일럿에서 호출하지 않는다.
- 각 카드와 선택 요소는 키보드 초점이 보이고 모바일 터치 영역이 최소 44×44 CSS 픽셀이라는 제안 기준을 적용한다.
- 전환 검토 시 기존 화면과 신규 모형의 제목·이미지·가격·설명 및 항목 수를 비교한다. 예상 밖 차이가 있거나 읽기 외 호출이 발견되면 신규 경로를 중지하고 유지된 기존 MainList 표시 경로로 되돌리는 계획을 사용한다.

## 완료 기준

- [ ] 0개, 1개, 다수 항목 자료에서 각각 empty, 카드 1개, 입력 수와 동일한 카드 수가 표시되며 항목 누락이 0건이다.
- [ ] loading, empty, error, ready와 이미지 누락 상태가 서로 시각적·의미적으로 구분되고, 빈 결과를 오류로 표시하지 않는다.
- [ ] 각 ready 카드가 itemId, title, price, content, imgUrl 계약을 사용하며 기존 화면 대비 제목·이미지·가격·설명의 예상 밖 정보 차이가 0건이다.
- [ ] Firebase 조회를 교체 가능한 호스트 어댑터가 담당하고 표시 부품에서 네트워크 요청 및 Firebase 경로 참조가 0건인 설계로 검토된다.
- [ ] 클릭, Enter, Space 각각에서 select(itemId)가 한 번 발생하고 저장·주문·결제·찜·분석 호출은 0건이다.
- [ ] item.Url을 카드 입력이나 직접 이동 근거로 사용하지 않으며, 목적지 결정은 select 이후 호스트 책임으로만 정의된다.
- [ ] 이미지 누락·로드 실패·허용되지 않은 외부 출처에서 대체 영역이 표시되고 카드의 제목·가격·설명은 계속 읽을 수 있다.
- [ ] 긴 제목·설명과 모바일 폭에서도 가로 넘침이 없고, 모든 선택 카드에 보이는 키보드 초점과 최소 44×44 CSS 픽셀 조작 영역이 있으며, 회귀 실패 시 기존 경로로 되돌리는 절차가 문서화된다.

위 항목은 향후 위젯 구현의 검증 기준이며 지금 구현 테스트가 통과했다는 의미가 아니다.

## 미확인

- 실제 Firebase /itmes.json 응답에서 title, price, content, imgUrl의 누락 가능성, 자료형 및 가격 통화 형식은 확인되지 않았다.
- item.Url의 실제 대소문자, 생성 위치, 기존 링크 목적지와 itemId 간 대응 규칙은 확인되지 않았다.
- 기존 화면에서 이미지 누락, 빈 결과 및 긴 문구를 처리하는 실제 방식은 앱 실행 없이 확인할 수 없다.
- 운영 인증·권한·오류 응답·시간 제한 및 고객별 데이터 공급자 분리는 정적 보고서만으로 확정할 수 없다.
- MIMO와 KMovement의 코드·데이터·외부 이미지에 대한 상용 재사용 권리는 확인되지 않았다.
- 실제 모바일 브라우저, 보조기술 및 키보드에서의 동작과 기존 고객 화면의 완전한 동등성은 별도 실행 검증이 필요하다.
- 기존 화면을 유지하면서 신규 모형을 선택적으로 끄는 기능 플래그나 라우팅 장치의 현재 존재 여부는 확인되지 않았다.
