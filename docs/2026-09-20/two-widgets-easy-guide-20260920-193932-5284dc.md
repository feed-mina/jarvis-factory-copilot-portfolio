# 두 위젯을 완성해서 도구함에 넣기

> 목표: MIMO 상품 카드와 KMovement 장소 카드를 하나씩 완성하고, SDUI-template에서 불러와 사용할 수 있게 한다.

현재 상태: 실행 전 가이드. 예상안 검토와 실제 구현·등록은 별도. 두 번째 대상은 기존 비교 대상 KMovement 장소 카드로 잡음.

## 3줄 줄거리

1. 두 카드의 표시·이동 범위를 정한다.
2. MIMO 제작·등록 후 KMovement를 같은 순서로 진행한다.
3. 두 카드의 저장 후 재열기와 실제 클릭을 확인한다.

## 현재 위치

두 위젯 완성 > 첫 MIMO > 제작 시작 기준 정리.

## 순서

범위 → MIMO 제작 → MIMO 등록 → KMovement 제작·등록 → 통합 검사. 실패 시 해당 단계 보완.

## 두 위젯의 첫 버전 정하기

**현재 상황**: 상품은 사진·이름·가격·상세 열기, 장소는 사진·이름·주소·상세 열기까지입니다. 장소 찜은 이번 두 위젯 완료 범위에서 제외하는 제안입니다.

**내가 할 일**: 상품·장소의 첫 버전 범위를 확인합니다.

**도우미에게 부탁할 말**: 두 카드에 보여줄 내용과 눌렀을 때 할 일을 먼저 정리해 주세요.

**끝났는지 확인**: 각 위젯의 표시 항목·클릭 결과·제외 기능을 한 장에 적습니다.

**안 되면**: 두 범위가 섞이면 공통 모양과 각자의 기능을 다시 나눕니다.

## 첫 번째: 상품 카드

**현재 상황**: 예상 그림과 문서는 있지만, 이 자료만으로 작동하는 위젯이 완성됐다고 볼 수 없습니다.

**내가 할 일**: 예상 화면에서 가격과 상세 열기가 원하는 모습인지 봅니다. 제작 시작은 별도 구현 요청으로 지시합니다.

**도우미에게 부탁할 말**: 상품 카드 하나를 만들어 주세요. 사진이 없거나 상품이 없을 때도 알아보기 쉽게 해 주세요. 누르면 맞는 상품이 열리는지 확인해 주세요.

**끝났는지 확인**: 같은 상품 자료로 이전/이후 실제 실행 화면, 클릭 결과, 검사 결과와 변경 파일을 받습니다.

**안 되면**: 이동 주소를 모르면 임의 주소를 만들지 않고 그 카드의 열기를 막습니다.

## 상품 카드를 도구함에 넣기

**현재 상황**: 파일을 GitHub에 올리는 것만으로 SDUI-template에서 쓸 수 있게 되지는 않습니다.

**내가 할 일**: 도구함에서 상품 카드를 골라 새 화면에 넣고, 저장한 뒤 다시 열어 봅니다.

**도우미에게 부탁할 말**: 상품 카드를 도구함에서 골라 쓸 수 있게 해 주세요. 저장하고 다시 열어도 같은지 보여 주세요.

**끝났는지 확인**: 실제 Studio 화면에서 불러온 상품 카드, 저장 후 재표시, 상품 클릭 동작, 패키지 검사 결과를 받습니다.

**안 되면**: 미리보기만 보이고 클릭이 안 되면 표시와 동작 연결을 각각 고칩니다.

## 같은 방법으로 장소 카드 완성

**현재 상황**: 상품 카드의 공통 모양을 재사용하되, 가격 대신 주소를 보여줍니다.

**내가 할 일**: 장소의 주소와 상세 열기를 확인합니다. 찜이 꼭 필요한 경우 범위를 다시 정합니다.

**도우미에게 부탁할 말**: 이제 장소 카드도 만들어 도구함에 넣어 주세요. 상품의 가격 대신 장소의 주소가 나오게 해 주세요.

**끝났는지 확인**: 상품 가격과 장소 주소가 섞이지 않고, 두 카드가 한 화면에서도 각각 올바르게 열립니다.

**안 되면**: 공통으로 묶느라 조건문이 늘면 데이터 변환을 각각 분리합니다.

## 두 개를 실제로 쓰기

**현재 상황**: 완료는 문서 수나 모델 점수가 아니라 직접 사용한 결과로 판정합니다.

**내가 할 일**: 두 위젯을 새 화면에 넣고 휴대폰 폭에서도 각각 눌러 봅니다.

**도우미에게 부탁할 말**: 두 카드를 함께 넣고 각각 눌러 봐 주세요. 잘된 화면과 아직 안 되는 부분을 나눠 알려 주세요.

**끝났는지 확인**: 두 위젯 모두 동일한 완료표를 통과합니다. 운영 URL에서 쓰는 목표라면 배포 후 확인까지 통과해야 합니다.

**안 되면**: 하나가 실패하면 그 위젯만 보완하고, 통과한 위젯의 증거는 유지합니다.

## 완료 확인표

- 상품 카드 / 사진·이름·가격과 안전한 상세 열기 / 실제 데이터 필드가 확인되지 않으면 샘플임을 표시

- 장소 카드 / 사진·이름·주소와 장소 상세 열기 / 찜 저장은 별도 범위

- 목록 상태 / 읽는 중·0건·실패·정상·사진 없음 / 각 상태가 구별됨

- 사용성 / 좁은 화면·긴 제목·키보드 조작 / 클릭과 키보드 선택이 한 번씩만 동작

- 등록 / 두 항목을 불러오기·저장·다시 열기 / 파일 업로드만으로 통과하지 않음

- 공통화 / 두 위젯을 같은 화면에 넣기 / 가격과 주소, 클릭 대상이 섞이지 않음

- 공개 사용 / 선택한 운영 주소에서 두 위젯 확인 / 배포를 포함할 때만 적용; 로컬 확인과 구분

## 현재 화면의 의미

- 프로젝트 화면: 개발 이력을 읽는 화면. 새로 읽기는 에이전트 실행이 아님.

- 에이전트 실행: 선택한 메일의 처리 흐름. 기록 없음은 해당 메일의 기록 상태이며 전체 장애 판정이 아님.

- Eval Studio / Release Gate: 메일 평가 결과. 위젯 두 개의 검사 결과가 아님.

- 예상안 자동 피드백: 기존 실행 기록은 예상안 검토 후 사용자 검토 대기. 위젯 코드 제작 기능은 아님.

- 이번 산출물: 두 위젯 완성·등록을 위한 가이드. 제품 구현과 운영 배포는 이번에 실행하지 않음.

자료: 사용자가 제공한 Javis 화면 5장. 개인 메일 화면 원본은 GitHub에 게시하지 않음. HTML의 After는 미구현 예상 모형. 이번 산출물은 가이드이며 제품 코드·운영 환경 변경 없음.

## Before / After

Before(사용자 제공 실제 캡처): 프로젝트는 개발 이력 조회이고 에이전트 실행은 메일 선택 및 처리 단계이다. Eval Studio의 5건 통과는 메일 평가 결과이며 위젯 검사가 아니다.

After(미구현 제안): 별도 위젯 작업 화면에 MIMO/장소 카드별 현재 단계·결과 보고서·다음 행동·부족한 증거를 표시한다. MIMO는 제작 대기, 장소 카드는 MIMO 등록 통과 후 시작으로 보여준다. 도구함에서는 상품의 사진·이름·가격·상세 열기, 장소의 사진·이름·주소·상세 열기를 별도 항목으로 불러온다.

## 역할

- 사용자: 범위 결정, 예상 화면 확인, 최종 직접 사용.
- Javis: 진행 순서와 결과 검토, 부족한 부분 재요청. 현재 화면 연결은 별도 개발 대상.
- 개발 에이전트: 위젯 제작과 등록 및 실제 검사.
- 도구함: 두 위젯을 각각 선택해 사용.

## 공통으로 쓸 부분과 따로 둘 부분

사진·이름·목록 상태·선택 전달은 공유한다. 상품 가격·상품 이동과 장소 주소·장소 이동은 각각 유지한다. 장소 찜 저장은 이번 첫 버전에서 제외하는 제안이며 기존 기능은 변경하지 않는다.

## 뒤돌아보기와 검증 범위

두 위젯의 구현 완료를 현재 자료만으로 판정하지 않는다. 이번 문서의 다음 검증은 MIMO 한 개를 도구함에서 실제로 불러오는 것이다. HTML 정적 구조 검사 통과. 브라우저 상호작용·실제 제품 테스트·운영 배포는 이번 문서 작업에서 실행하지 않았다.
