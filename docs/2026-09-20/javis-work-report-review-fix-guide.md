# Javis 작업 전 보고서 검토 · Fix Guide

## 핵심 한 줄

Javis에 메일 답장과 분리된 **위젯 작업** 화면을 추가해 A01 보고서를 중복 없이 검토하고, 통과해도 코드·테스트·PR까지만 진행하며 main 병합·운영 배포는 사용자 확인에서 멈춘다.

## 현재 위치

전체 목표 중 **A01 보고서를 Gmail에서 받아 Javis가 판정하는 파트**를 구현했다. Javis가 판정을 A01에 전달하고 A03 실행을 시작하거나 이메일·Telegram 알림을 보내는 파트는 다음 작업이다.

## 확인한 문제

기존 Javis의 메일 작업실은 받은 메일을 분류하고 답장 초안을 검토하는 기능이다. 작업 전 보고서를 하나의 개발 작업으로 묶는 식별자, 재발송 중복 제거, 개발 범위 판정, HTML 보고서 링크가 없었다.

현재 MIMO `MIMO-R06-W01-PREWORK-v1.0.0` 보고서는 제외 범위에 `commit·push`가 들어 있다. 이는 “검토 통과 후 코드 수정·테스트·PR 작성” 정책과 충돌하므로 바로 통과시키면 안 된다.

## 사용자에게 보이는 변화

### Before

- 메일 작업실과 에이전트 실행 화면만 있음
- 작업 전 보고서와 일반 메일이 구분되지 않음
- 원본과 재발송이 각각 실행될 위험을 판정할 화면이 없음

### After

- 상단에 `위젯 작업` 메뉴가 생김
- 작업 ID·보고서 버전·연결 메일 수·검토 상태를 표시
- 같은 첨부 내용을 다시 보내면 새 작업을 만들지 않고 연결 메일 수만 증가
- 필수 계약 검사와 Javis 판정, A01 보완 내용을 표시
- 첨부 HTML은 화면에서 실행하지 않고 인증된 다운로드로 제공

## 처리 흐름

```text
사용자 → 목표·허용 범위 전달
  ↓
A01 → 작업 전 보고서 작성·이메일 전송
  ↓
Javis 위젯 작업 → 발신자·작업 ID·버전·첨부 다이제스트 확인
  ├─ 같은 내용 재발송 → 기존 보고서에 연결, 재실행 없음
  ├─ 필수 항목/권한 충돌 → A01 보완 필요
  ├─ 사용자만 정할 범위 → 사용자 판단 필요
  └─ 계약 통과 → 도구 없는 A01 모델 검토
       ├─ 반려 → A01 보완 필요
       └─ 통과 → 코드·테스트·PR 단계 연결 가능
                    ↓
             main 병합·운영 배포는 사용자 확인 대기
```

## 핵심 기능과 파일

| 기능 | 파일 | 역할 |
|---|---|---|
| Gmail 보고서 검색·첨부 읽기 | `server/gmail.py` | 검색 쿼리와 첨부 다운로드 |
| 식별·중복 제거·계약 검사·A01 판정 | `server/work_reports.py` | 작업 ID/버전/다이제스트, 권한 경계, 도구 없는 검토 |
| DB/API | `server/api.py` | 목록·상세·이력·수집·검토·HTML 다운로드 |
| 브라우저 허용 목록 | `scripts/live-bridge.mjs` | 알려진 작업 보고서 경로만 프록시 |
| 위젯 작업 화면 | `src/v2/WorkReportsConsole.tsx` | 상태·검사·판정·HTML 링크 표시 |
| 메뉴/라우팅 | `src/v2/LiveConsole.tsx` | 기존 메일 화면과 별도 경로 연결 |
| 검증 | `server/test_work_reports.py`, `scripts/live-bridge.check.mjs` | 중복·권한·HTML·브리지 검사 |
